# Passthrough Lab

A small PS5 homebrew app that sends **Dolby Digital, Dolby Digital Plus (including Atmos), DTS and AAC** over HDMI untouched, so your soundbar or AV receiver does the decoding. It's built on [ps5-homebrew-ui](https://github.com/blackbearreloaded/ps5-homebrew-ui) and doubles as a hardware test: every number the console returns is on screen.

It runs as an ordinary sandboxed app. It doesn't need a sandbox escape or any kernel access.

## What works (PS5 Pro, firmware 12.70, 2026-10-08)

| Clip | Format | Console mode | Result |
|---|---|---|---|
| `ac3-5.1-448k.ac3` | Dolby Digital 5.1 | 0, 48 kHz | plays, receiver decodes |
| `eac3-5.1-640k.eac3` | Dolby Digital Plus 5.1 | 3, 192 kHz | plays, receiver decodes |
| `dts-5.1-768k.dts` | DTS 5.1 (core) | 2, 48 kHz | plays, receiver decodes |
| `aac-5.1.aac` | AAC 5.1 (ADTS) | 1, 48 kHz | plays, receiver decodes |
| `local-atmos.eac3` (yours, not shipped) | Dolby Digital Plus + Atmos | 3, 192 kHz | plays |

Not yet: Dolby TrueHD (Blu-ray Atmos) and DTS-HD. They need the HDMI high-bitrate mode, and which console mode carries them isn't known yet.

The bundled clips are royalty-free channel-ID tones generated by `../tools/make-clips.sh`. Each speaker beeps in turn (front left, front right, centre, subwoofer, surround left, surround right), so a wrong channel map is easy to hear.

## Using it

| Button | Action |
|---|---|
| D-pad | pick a clip |
| ✕ | play it as a bitstream |
| ○ | stop |
| □ | loop on/off |
| △ | read the receiver's format list again (after switching inputs, for example) |

The right side shows what your TV or receiver says it can decode (read over HDMI), and the live result: the port handle, the switch's return code, bursts sent, errors and time.

While a bitstream plays, the console mutes all other sound from the app, including the menu sounds. That's how the PS5 handles bitstream mode, not a bug.

## Building

The build needs Linux or WSL with clang 18, or any Docker image with the PS5 toolchain (EVO Player's `evo-player/ps5-dev` image works). From this folder:

```bash
make init TITLE_ID=PPSA99051 APP_NAME="Passthrough Lab"   # already done; change the ID if it clashes
make ffpfsc                                              # -> dist/PPSA99051.ffpfsc
```

With Docker on Windows:

```bash
MSYS_NO_PATHCONV=1 docker run --rm -v "<path>/sample-app:/w" -w /w evo-player/ps5-dev:llvm18-sdk-v0.42 make ffpfsc
```

The first build downloads the pinned PS5 payload SDK into `.deps/`. **On Windows, clone with `core.autocrlf=false`.** With CRLF line endings, the runtime checksum check fails ("runtime checksum manifest does not match the release digest").

Install: copy `dist/PPSA99051.ffpfsc` to `/data/homebrew/` on the console (FTP) and start it from the home screen (ShadowMount+). Close the app before replacing the file.

### Adding your own clips

Put elementary-stream files (`.ac3`, `.eac3`, `.dts`, `.aac`) in `assets/clips/` and list them in `index.txt`. The console can't list folders under `/app0`, so the index is required. Clips cut from files you don't own go in `local-*` names and `index.local.txt`, which git ignores:

```bash
ATMOS_SOURCE="some Atmos file.mp4" ../tools/make-clips.sh   # cuts local-atmos.eac3
```

## Where the code is

| File | What it does |
|---|---|
| `src/passthrough/iec61937.cpp` | finds frames in AC-3, E-AC-3, DTS and ADTS AAC streams and wraps them in IEC 61937 bursts. Plain C++, no PS5 calls. |
| `src/platform/ps5/bitstream_out.cpp` | the console side: `sceAudioOutExOpen` → `sceAudioOutExConfigureOutput` → `sceAudioOutOutput` → close → restore; and the receiver's format list |
| `src/passthrough/bitstream.hpp` | the small interface between the two, so the screen also builds for the PC preview (`host/bitstream_host.cpp` pretends) |
| `src/concepts/passthrough.cpp` | the screen |

To add passthrough to your own app, copy the first two files. You need nothing else from the kit.

Two traps found on the way:

- **Link the functions; don't look them up.** `sceKernelDlsym` is refused in a sandboxed app. The SDK's `libSceAudioOut` stub already exports `sceAudioOutExOpen`, `sceAudioOutExClose`, `sceAudioOutExConfigureOutput` and `sceAudioOutSysGetHdmiMonitorInfo`, so just declare them `extern "C"`.
- The kit's `save::read_file(path, &data, max)` fails on any file bigger than `max`. It's a size limit, not a read length.

The app logs to `/mnt/sandbox/PPSA99051_000/download0/hui/dev/app.log`, readable over FTP while it runs. Lines start with `[PT]`.
